# アカウント変更の管理・通知・確認（相談中）

更新日：2026-10-17

## 目的・範囲

[会社・業務の前提](business-context.md)と[認証・認可の要件](authentication-authorization.md)に基づく、PR #7以降の合意事項です。購買・備品管理を中心とし、アカウント変更のための汎用ワークフローには広げません。実装順序・初期リリース範囲は別途決めます。

## 担当者と反映方式（合意済み）

| 役割 | 担当 |
| --- | --- |
| 異動・昇進等の決定 | 人・会議体は未決定。システム課が決定するものではない |
| 決定情報の管理・変更依頼 | 総務課 |
| 登録・所属変更・役職変更・利用停止・停止解除の操作 | システム課全員 |
| 変更結果の確認 | 総務課長が主担当。管理部長も確認可能で、どちらか1人が確認すれば完了 |
| 誤りの修正・必要な停止 | システム課へ依頼する。総務課に停止操作の権限は追加しない |

システム課の操作で即時反映し、その後に確認します。担当者不在で操作を止めないこと、要件を複雑にしすぎないことを優先します。誤った権限が修正・停止まで有効になる可能性は残り、履歴による追跡と修正で対応します。

## 変更履歴と修正（合意済み）

- アカウントの全変更について、対象社員・操作者・日時・変更前後・理由・会社の決定を確認できる情報を残します。
- 総務課長または管理部長が確認し、確認者・確認日時を記録します。履歴を眺めるだけでなく、正式な人事情報・依頼との一致を確認する目的です。
- 誤りを発見したら理由を記録して修正依頼とし、システム課全員へ通知します。管理職不在でも対応でき、誤った状態を早く解消するためです。
- 修正時に元の履歴を上書きせず、修正操作も別に記録し、元の変更・修正依頼・修正・確認を追えるようにします。
- 修正後に総務課長または管理部長が結果を再確認して完了にします。
- 誤った状態の開始・解消時刻と、誤りの発見・確認完了時刻を区別します。例：10:00誤変更、11:00発見、11:20修正、13:00確認なら、誤った状態の期間は10:00〜11:20です。
- 誤った期間の業務操作まで調査するための購買等の操作履歴は今後詳細化します。その期間の全操作を自動的に誤りとみなすものではありません。

修正の担当調整は課内運用とし、アプリ上の対応開始・担当割当・進捗管理は採用しません。反映前の2段階承認、確認担当者による緊急停止も今回は採用しません。

## 最初の確認依頼・通知（合意済み）

| 変更 | 通知先・タイミング |
| --- | --- |
| 新たに管理・承認・確認権限を持つ変更 | 総務課長へ即時通知・確認依頼 |
| 利用停止の解除 | 総務課長へ即時通知・確認依頼 |
| その他の変更 | 毎営業日8:00から総務課長へまとめて確認依頼を送信し、9:00までの送信完了を目指す |

通常の変更を朝に送る理由は、9:00の業務開始時に確認し、1日の予定を組みやすくするためです。受信側の配送遅延まで保証するものではありません。

- まとめ通知は、前回までに依頼していない変更が対象です。休業日中の変更は次の営業日に含め、対象がなければ送りません。
- 即時依頼済みの変更について、まとめ通知を理由に期限を延長しません。
- 即時通知は営業日のまとめ処理とは別です。休日・夜間に変更された場合の即時通知にも、期限超過通知の営業日ルールを流用しません。

### 権限が増える変更の範囲

| 対象 | 理由 |
| --- | --- |
| システム課への配属・異動 | アカウント管理が可能になる |
| 非管理職から課長・部長への変更 | 購入申請の承認が可能になる |
| 課長から部長への変更 | 承認範囲が広がる |
| 課長・部長の担当組織の変更 | 以前は扱えなかった課・部署の申請を扱えるようになる |
| 総務課長・管理部長への就任 | アカウント変更の確認が可能になる |

新規登録時からこれらの権限を持つ場合も即時通知します。一般社員としての登録は通常のまとめ通知です。権限の数や昇進の有無ではなく、新たに操作できる対象・機能があるかで判断します。

## 確認期限と管理部長への通知（合意済み）

すべて日本時間です。

| 項目 | ルール |
| --- | --- |
| 営業日 | 土日・日本の祝日・会社指定の休業日を除く日 |
| 起算 | 確認依頼日は数えず、翌営業日を1営業日目とする |
| 確認期限 | 3営業日目の7:00直前まで（6:59台を含む） |
| 通知開始 | 3営業日目の7:00から、未確認分の管理部長への通知処理を開始 |
| 送信時の判定 | 各通知の送信直前にも確認状況を確認し、確認済みなら送らない |
| 個人の休暇 | 有給休暇等で期限を延長しない |
| 完了 | 総務課長・管理部長のどちらか1人が確認すれば完了 |

7:00ちょうどに全件送信完了する要件ではありません。管理部長への通知後も総務課長は確認可能です。休日の確認までは求めないため、休日を挟んで確認の遅れが長くなる場合は許容します。

以前検討した「2営業日目23:59期限」「その翌暦日7:00に休日でも通知」は採用せず、上記に置き換えます。

### 確認例

| 条件 | 期待する結果 |
| --- | --- |
| 水曜日に依頼、祝日・会社休業日なし | 木・金・月と数え、月曜7:00直前までに確認。7:00から未確認分を通知 |
| 同条件で月曜日が祝日 | 木・金・火と数え、火曜7:00から未確認分を通知 |
| 課長が有給休暇中 | 期限を変更しない |
| 通知の送信前に管理部長または総務課長が確認済み | その通知を送らない |
| 休日に権限が増えない変更を実施 | 次の営業日8:00からまとめて依頼。変更日ではなく依頼日を起算の基準とする |
| 即時依頼済みの変更が翌営業日を迎える | 確認期限を延長しない |

## 未決定事項・実装前に確認する点

- 会社指定休業日の登録担当・カレンダーの更新方法。
- 確認依頼日時の記録基準（送信失敗時を含む）、送信の再試行・重複防止、通知先不在・未設定時の扱い。
- 修正依頼中・再確認時の期限と通知、管理部長への通知後も未確認の場合の再通知。
- 全変更を記録する方針と、一時制限解除・リンク送信等の補助操作を事後確認対象へ含める範囲の切り分け。
- 履歴の保存期間・閲覧権限・改変防止の具体策、本人に関する変更を確認する場合の扱い。
- 履歴だけでは変更し忘れを検知できないため、未処理の依頼と登録結果を照合する方法。総務課からの依頼そのものをアプリに登録する機能は未決定。
- 人事情報の適用日、予約変更の必要性、所属・役職変更と承認待ちの購入申請の関係。
