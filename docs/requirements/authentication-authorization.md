# 認証・認可と購入承認の要件（相談中）

更新日：2026-10-17

## 目的と読み方

認証・認可の要件定義を作成するための途中記録です。[会社・業務の前提](business-context.md)を共通の前提とします。合意済みのルール、理由、確認例、未決定事項を分けます。この文書だけで実装を開始できる状態ではありません。

| 用語 | 意味 |
| --- | --- |
| 認証 | 利用者が誰であるかを確認すること |
| 認可 | 利用者が対象のデータ・操作にアクセスしてよいかを判断すること |
| 承認フロー | 申請について誰がどの順序で承認するかという業務ルール |
| 申請者 | 部署の購入申請を提出する人 |
| 利用者 | 購入する備品を実際に使う人。申請者とは限らない |
| 承認判定額 | 承認ルートの決定に使う金額。支払額・予算確保額とは区別する |

## 認証・アカウント（合意済み）

PR #7以降の相談内容を反映しています。要件の合意と初期リリースへの採用は区別し、実装順序・技術・ライブラリは未選定です。セキュリティを重視する方針です。

### ログイン方式と将来のSSO

- 初期はアプリ専用アカウントを使い、会社のメールアドレスとパスワードでログインします。一般向けの新規登録は設けません。
- メールアドレスとは別に変更しない内部利用者IDを持ち、メール変更や将来のSSO移行でも申請・承認・操作履歴を同じ利用者に結び付けます。
- 利用者の識別、認証情報、所属・役職・操作権限を分けて扱います。SSOの方式・連携先・移行手順は未決定で、SSOによる所属・役職の自動連携も決定していません。
- アカウントの管理担当と事後確認は[アカウント変更の管理](account-administration.md)に従います。

### 初期パスワード設定・再設定

| 項目 | 初期設定 | パスワードを忘れた場合 |
| --- | --- | --- |
| 開始 | システム課が社員を登録し、システムが案内を送信 | 本人がチャットまたは電話でシステム課へ依頼 |
| 送信先 | 登録済みの社用メール | 登録済みの社用メール |
| リンクの有効期限 | 発行から24時間 | 発行から30分 |
| 期限切れ | システム課へ再発行を依頼 | システム課へ再発行を依頼 |

- 有効期限は営業日ではなく経過時間で判定します。利用者自身が再設定メールを要求する画面は初期範囲では設けません。
- 再設定依頼では社員番号・氏名で対象アカウントを特定します。この情報だけを依頼者の本人証明にはしません。
- システム課は送信操作を行い、システムがメールを送ります。依頼者が指定した別アドレスへは送りません。受信できない場合の別途対応は未決定で、この手続きのついでに送信先を変更しません。
- 本人がリンク先でパスワードを設定します。パスワード自体はメールで送らず、システム課にも知らせません。管理画面には設定リンク自体を表示しません。
- リンクは推測困難・一度限りとし、HTTPSの設定画面を使います。設定完了で使用済みとし、再発行時には以前の同用途のリンク、利用停止時には全設定リンクを無効にします。
- リンク送信だけでは現在のパスワードやログイン状態を無効にしません。誰が、誰のリンクを、いつ送ったかを記録します。
- 初期設定前はアカウントが存在しても業務機能へログインできません。
- 再設定完了時は全端末のログイン状態を無効にします。再設定した端末も自動ログインせず、新しいパスワードでログインし直します。再設定によって利用停止を解除しません。

### パスワード条件

| 項目 | 決定内容 |
| --- | --- |
| 長さ | 15〜128文字 |
| 許可文字 | 半角英数字・半角記号・通常の半角スペース（ASCIIのU+0020〜U+007E） |
| 不許可文字 | 日本語・全角文字・タブ・改行・その他の空白など、上記範囲外の文字 |
| 文字種の強制 | 大文字・小文字・数字・記号をそれぞれ含める義務は設けない |
| 弱いパスワード | よく使われるもの、漏えいが知られているもの、サービス名・利用者名等から容易に推測できるものを拒否 |
| 定期変更 | 求めない。漏えいが確認された場合などに変更を求める |
| 入力値 | 先頭・末尾の半角スペースも保持し、勝手に削除・置換しない。不許可文字は設定時に説明して拒否 |

日本語・Unicodeの許可は、入力の分かりやすさと検証範囲を優先して今回は採用しません。日本語が危険という判断ではありません。128文字は本アプリの選択であり、標準が指定した上限ではありません。弱いパスワードの照合方法・リストの調達と更新は未決定です。

### 利用停止・解除

- 人事区分とは別に利用可能／利用停止を管理し、停止理由を記録します。初期設定前やログイン一時制限とは区別します。
- 停止・解除は総務課の依頼に基づきシステム課全員が操作できます。退職も利用停止とし、過去の申請・操作履歴を削除しません。詳細な病名などは記録しません。
- 利用停止時は新規ログインと全端末からの以降のアクセスをサーバー側で拒否し、発行済みの初期設定・再設定リンクも無効にします。完了済みの業務操作を取り消すものではありません。
- 解除では理由・操作者・日時を記録し、総務課長へ即時通知します。以前のログイン状態や無効化したリンクは復活させません。本人が改めてログインし、必要なら別途パスワード再設定を行います。

### ログイン状態（セッション）

| 項目 | 決定内容 |
| --- | --- |
| 無操作期限 | 最後の操作から1時間 |
| 継続時間の上限 | 操作の有無によらずログインから12時間 |
| 利用中と扱う操作 | 入力・画面遷移・保存など。入力中も無操作とは扱わない |
| 延長しない動作 | 画面を開いているだけ、通知などの自動取得だけ |
| 期限到達 | サーバー側でも無効化し、再ログインを求める |
| 通常のログアウト | 操作したブラウザーのログイン状態のみ終了。同じ状態を共有するタブも終了 |
| 同時ログイン | 複数端末・ブラウザーを許可。新規ログインで既存のログインを終了させない |
| 期限の独立性 | ログインごとに期限を管理し、別端末の操作では延長しない |

入力中の利用状況をサーバーへ伝える方法は設計時に決めます。下書き保存は予定機能ですが、自動保存や期限前警告、保存後の未保存入力の扱いは未決定です。

### ログイン失敗と一時制限

- 同一アカウントで直近15分間に5回失敗したら、5回目から15分間ログインを制限します。
- 制限中の試行で期限は延長しません。時間経過で自動解除するほか、システム課全員が手動解除できます。
- 自動・手動解除時とログイン成功時に失敗回数をリセットします。
- 手動解除では対象者・操作者・日時・理由を記録します。利用停止状態やパスワードは変更しません。
- 制限開始を登録済みの社用メールへ通知します。同一アカウントへの通知は前回送信から1時間以上空けます。ログイン成功で通知間隔はリセットしません。
- メール未登録、パスワード誤り、利用停止、一時制限をログイン画面では区別せず、次の共通表示にします。

> ログインできませんでした。入力内容をご確認ください。解決しない場合はシステム課へお問い合わせください。

### 認証の確認例

| 条件 | 期待する結果 |
| --- | --- |
| 初期設定リンクの発行から24時間が経過 | 設定できず、再発行が必要 |
| 再設定リンクの発行から30分が経過 | 設定できず、再発行が必要 |
| 再発行後に以前のリンクを使用 | 拒否 |
| 再設定リンクを送信しただけ | 既存パスワード・ログイン状態は維持 |
| 再設定を完了 | 全端末で再ログインが必要 |
| 利用停止後に停止前のログイン状態でアクセス | サーバー側で拒否 |
| 停止を解除 | 古いセッション・リンクは復活しない |
| 入力などの操作を継続 | 無操作期限は更新するが、ログインから12時間で終了 |
| 自動取得のみが続き、最後の操作から1時間が経過 | ログイン状態を無効化 |
| PCで通常ログアウト | 同じ状態のタブは終了し、別端末のログインは維持 |
| 10:00〜10:04に5回失敗 | 10:04から10:19まで一時制限。追加試行で延長しない |
| 失敗後にログイン成功 | 失敗回数をリセット。メール通知間隔は維持 |
| 長さ14文字／15文字／128文字／129文字 | 長さ判定は拒否／許可／許可／拒否。他の条件も別途確認 |

### 認証で未決定・提案段階の事項

- IP制限は追加候補。採用範囲、拠点のIP、在宅勤務・VPNの扱いは未決定です。
- パスワード管理ツールの自動入力・貼り付けの許可、表示切替は提案段階です。
- 認証失敗理由の内部記録と閲覧権限、パスワード等の秘密情報をログへ出さない具体設計。
- アクセス元ごとの試行制限、再設定メール等の連続送信対策、未登録アドレスに対する内部処理。
- 本人による通常のパスワード変更、メールアドレス変更時の確認、メールを受信できない場合の復旧。
- 一時制限中の既存セッション、パスワード再設定と一時制限の関係。
- 初期管理者の準備、最後の管理者を失った場合の復旧、MFAの採否、SSO移行の詳細。

## 購入申請と承認（合意済み）

### 申請・承認できる人

- 非管理職社員と課長が購入申請を提出できます。部長は購入申請を提出しません。
- 申請者本人による承認は禁止します。
- 通常、非管理職社員の申請は、その社員の所属する課の担当課長が承認します。同じ部署の課長なら誰でも承認できる、というルールではありません。
- 部長承認は、申請する部署の部長が担当します。
- 申請者以外の社員・部長が使う備品や、共用備品も申請できます。
- 社員が部署として部長用の備品を申請し、その部長が承認することを許可します。部長本人の名義で入力だけを代行する「代理申請」とは区別します。

### 承認ルート

以下は通常の承認ルートです。基準金額は支払形態ごとに設け、具体的な値は未決定です。

| 申請者 | 承認判定額 | 承認ルート |
| --- | --- | --- |
| 非管理職社員 | 基準金額未満 | 担当課長で完了 |
| 非管理職社員 | 基準金額以上 | 担当課長 → 所属部署の部長 |
| 課長 | 金額を問わない | 所属部署の部長 |
| 部長 | 金額を問わない | 申請不可 |

基準金額ちょうどの場合は「以上」に含みます。高額の場合に課長承認を飛ばして部長へ直接回すルールではありません。ただし、課長自身の申請は部長へ直接回します。

### 判断理由と責任

部署の予算で購入するため、部長が支出の妥当性と利益相反を含む判断に責任を持つ、という架空の会社の業務前提です。利益相反が起きた場合も部長が責任を持つ方針であり、利益相反自体を許可する意味ではありません。法的責任の所在を定めるものでもありません。

この方針により、申請者と承認者は分けますが、備品の利用者と承認者が同一であることまでは禁止しません。部長用の備品のために社長への承認経路を追加する案は採用しません。

## 金額判定（合意済み）

| 支払形態 | 承認判定額 | 比較対象 |
| --- | --- | --- |
| 単発購入 | 購入金額 | 単発購入用の基準金額 |
| 継続的な支払い | 年額に換算した金額。固定月額なら月額×12、固定年額なら年額 | 継続支払い用の年額基準金額 |

- 短期利用の予定でも一律12か月分で判定します。実際の支払総額より大きい判定額となり、承認ルートが厳しくなる場合も許容します。
- 理由は、予算を1年単位で考える想定と、解約遅れなどで予定より利用が長引く可能性を踏まえて判断したいためです。年度の開始月などは未決定です。
- 年額換算は年払い契約を強制するものではありません。また、予算の確保や支出の上限を保証するものでもありません。
- 「開始から12か月」と「当該年度の残り期間」は異なります。年度予算の扱いは今後検討します。
- 年額換算で判定しても、契約延長・更新まで承認されたことには自動的になりません。承認の有効範囲は未決定です。

### 確認例（正式な基準金額ではない）

以下は会話で使った例を含むルール確認用の仮の値です。正式な基準金額や税込・税抜を決定するものではありません。

| 条件 | 期待する結果 |
| --- | --- |
| 非管理職社員、固定月額1,000円、継続支払いの仮基準15,000円 | 年額換算12,000円で、担当課長の承認で完了 |
| 同条件で利用予定が3か月 | 3,000円ではなく12,000円で判定 |
| 非管理職社員、承認判定額が基準金額と同額 | 担当課長 → 部長 |
| 課長自身の申請、承認判定額が基準金額未満 | 部長 |
| 部長が申請を提出しようとする | 提出を許可しない |
| 部長用の備品を非管理職社員が申請し、判定額が基準金額以上 | 担当課長 → 部長。部長が利用することだけを理由に拒否しない |
| 同じ部署の別の課長が、代理の指定なしで承認しようとする | 通常の担当範囲外なので許可しない |

## 例外・別機能・将来候補

| 項目 | 状態 |
| --- | --- |
| 代理承認 | 必要なケースとして合意済み。別の課長へ承認を依頼する想定。指定者、代理人の範囲、有効期間、実装時期は未決定 |
| 取引先追加 | 購入申請とは別機能にする方針。取引先の新規・既存は今回の承認ルート分岐条件にしない |
| その他の分岐 | 予算内外、品目、費用負担部署、標準品かどうかは、現時点では分岐条件に含めない |
| 予算管理 | 確保・消化・解除・残額管理は今後の機能候補。今回の詳細化の対象外 |
| 解約忘れの通知 | 提案段階。採用・実装時期は未決定 |
| 監査記録 | アカウント変更・修正・確認の履歴は合意済み。詳細は別文書。購買業務の操作記録の具体項目・保存期間・閲覧権限は未決定 |

## 未決定事項・提案（実装上の既定値にしない）

### 金額・契約

- 単発購入・継続支払いそれぞれの正式な基準金額、税込・税抜、端数・通貨の扱い。
- 数量・利用人数を含む合計額、初期費用、値引き、料金変更の扱い。
- 従量課金、複数年契約、最低利用期間がある契約の扱い。
- 承認対象の期間・契約内容、利用延長・更新・増額時の再承認。
- 固定料金の月払い・年払いだけを初期対象にし、初期費用付き・従量課金・複数年契約を初期対象外にする案は、まだ提案段階です。

### 認可・業務運用

- 申請の閲覧・編集・取消範囲、差戻し・却下・再申請の動作。
- 申請後の金額変更、部署異動、担当課長・部長の変更、不在時の扱い。
- 代理承認と自己承認禁止の関係、承認途中での権限変更の扱い。
- 備品管理・発注・取引先登録の担当者と権限。アカウント管理はシステム課、事後確認は総務課長・管理部長と合意済み。
- 所属・役職変更時の既存セッションへの反映方法。アカウント管理権限を持つだけで購入承認権限も持つとは扱わない。
